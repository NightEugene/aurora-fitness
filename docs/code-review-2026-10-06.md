# Ревизия кода и документации — 06.10.2026

Исторический отчёт для 1.1.0. Актуальная ревизия: [code-review.md](code-review.md).

Проверены GUI/QML, D-Bus API и прокси, жизненный цикл демона, хранение SQLite,
транспорт/auth/иконки/синхронизация Mi Band, PineTime/MPRIS, сборка и документация.
Это проверка исходников и целевых сценариев, а не подтверждение всех BLE-сценариев.
PineTime в этой ревизии проверен по коду; аппаратная проверка требуется отдельно.

## Исправления

1. **Отключение уведомлений останавливало службу браслета.**
   `BandProxy::setDaemonEnabled()` вызывал `disable --now`, а включение удаляло
   юнит перед попыткой копирования из песочницы. GUI после рефакторинга зависит
   от постоянно работающего демона. Теперь переключатели сохраняют настройки
   и инициируют перечитывание через D-Bus, не управляя жизненным циклом службы.
2. **Уведомления о достижении цели использовали устаревшие цели.**
   `BluezManager::notifyGoalsAchieved()` брал поля, загруженные при старте
   демона. Теперь пороги читаются из настроек при проверке достижений.
3. **Повреждённый protobuf мог нарушить границы чтения.**
   В `pb::parse()` длина u64 приводилась к int до проверки; большие длины могли
   стать отрицательными/нулевыми. Незавершённые varint и повреждённый хвост
   принимались как данные. Теперь проверяется весь varint, номер поля и длина
   до сужения; повреждённое сообщение отвергается целиком. Убран signed shift
   отрицательных чисел из ZigZag-кодирования.
4. **DataUpload не проверял параметры ответа.**
   `chunkSize=4` приводил к делению на ноль, большие значения сужались;
   размер переносился из предыдущей загрузки. Добавлены проверки диапазонов,
   MD5, позиции возобновления и количества частей; начальный размер сбрасывается.
5. **Временные QDBusInterface оставались живы до конца BLE-сессии.**
   В `XiaomiChannel::pumpWriteQueue()` создавался объект на каждую запись.
   Теперь он освобождается после завершения соответствующего async-вызова.
6. **Идентификаторы иконок использовались как пути без проверки.**
   Hint отправителя и package браслета могли содержать разделители каталогов.
   Добавлена общая проверка компонента пути перед поиском и кэшированием иконки.
7. **Криптографические функции принимали ключи и nonce неверной длины.**
   Добавлены проверки длины перед OpenSSL и memcpy, проверка результата
   генератора случайных байтов и обработка невозможности создать nonce/шифротекст.
   Проверка всех возвращаемых кодов EVP остаётся отдельной задачей.
8. **Документация и список файлов сборки отставали от кода.**
   README теперь описывает службу, установку юнита, перезапуск после деплоя,
   архитектуру GUI/демона, полоски обложки и проверки. В qmake DISTFILES добавлен
   ProgressMarkers.js; поправлены комментарии про установку службы и errno=1.
   В AGENTS.md обновлены сведения о таблицах, переключателях и маркерах целей.

## Оставшиеся проблемы

### P1 — ACK файла не зависит от успешного сохранения

`app/src/xiaomi/activityfetcher.cpp`, `ActivityFetcher::addFilePortion()`:
после проверки CRC вызывается `fileParsed(parsed)`, затем безусловный `ackFile()`.
`Storage::saveParsed()` возвращает void; неподдержанный `kind=unknown` игнорируется,
ошибки INSERT/COMMIT не передаются загрузчику. ACK удаляет файл из очереди браслета.
Поэтому CRC-корректный неподдержанный файл или ошибка БД могут привести к потере
данных, даже если синк внешне завершился успешно.

Нужно: результат сохранения в цепочке Storage → BluezManager → канал/загрузчик,
ACK только после подтверждённого COMMIT; неподдержанные файлы сохранять как сырой
архив по явно определённой политике. Одного наличия отладочного дампа недостаточно:
успех его записи сейчас тоже не проверяется.

### P2 — таймаут/CRC-ошибка выдаются за успешный синк

`ActivityFetcher::onTimeout()` пропускает файл либо вызывает `finish()`,
а `finish()` всегда сообщает «Данные обновлены» и `finished()`.
`BluezManager` после этого записывает время успешной синхронизации.
Нужно различать успешную, частичную и неуспешную выгрузку; передавать результат
в GUI и автосинк, не обновляя время успеха при провале.

### P2 — несколько уведомлений во время отсутствия связи заменяют друг друга

`NotificationDaemon::handleNotify()` хранит единственную pending-запись.
Если браслет отключён или занят CLI, каждое следующее уведомление заменяет предыдущее.
Нужна ограниченная очередь с определённой политикой замены/устаревания и доставки.

### P2 — составные записи SQLite не гарантируют атомарность

`Storage::saveSleep()` отдельно записывает summary, удаляет старые stages и
вставляет новые без общей транзакции; ошибки stages игнорируются.
В `saveDailyDetails()`/`saveManualSamples()` результат transaction/commit
не проверяется, а activity_min обновляется отдельно от minute_samples.
Возможны неполная шкала сна и рассогласование сводки/деталей.
Это следует исправлять вместе с подтверждением сохранения перед ACK.

### P2 — getState и асинхронные команды не защищены от смены владельца имени

`BandProxy::onGetStateFinished()` принимает ответ без проверки поколения запроса.
Ответ/ошибка от старого владельца после рестарта демона или захвата имени CLI
может затереть более свежее состояние. `callDaemon()` игнорирует ошибки ответов.
Нужны поколение/владелец запроса и обработка ошибок команд; отдельно проверить
сценарии CLI → возврат имени демону и рестарта при открытом GUI.

### P3 — дополнительные ограничения

- При каждом открытии БД выполняются миграционные DELETE/UPDATE, даже из GUI.
  Нужна версия схемы и однократные транзакционные миграции.
- `bandInfo`, сканирование и сервисы прокси не полностью очищаются при отсутствии
  службы; устаревшие сведения могут выглядеть как актуальные.
- Массивы samples/stages в D-Bus снапшоте заменяются массивами нулей той же длины.
  Это сохраняет большой объём сообщений; UI достаточно количества записей.
- Проверка ACK загрузки иконки подтверждает передачу, но не её отображение
  на всех экранах Mi Band. Подтверждения для нашего пакета ещё нет.
- README заявляет BSD-3-Clause, но отдельного файла LICENSE в репозитории нет.

## Проверки

- `./tests/run.sh`: корректные/повреждённые protobuf, усечённые/переполненные
  varint, длины 2^32/u64, ZigZag отрицательных значений; AES-CCM round-trip,
  изменённый шифротекст, неверные ключ/nonce; компоненты путей иконок.
  Используются Qt 5.6 из SDK и UBSan с прекращением работы при UB.
- `./build.sh`: компиляция, подпись SDK и валидация RPM для трёх архитектур.
- Аппаратные проверки исходной версии перед ревизией: батарея/прошивка/GATT в GUI,
  обновление обложки после синка, подписи оси батареи, ориентация маркеров,
  одно сохранение цели после серии движений каждого ползунка.

Новые исправления прошли тесты и сборку для трёх архитектур. При подготовке
релиза 1.1.0 пакет установлен на Fplus MP-67A27: после перезапуска служба
активна, подключение готово, D-Bus возвращает батарею 26% и прошивку 2.3.14.
Это проверка запуска и связи; сценарии отказов из списка выше не проверялись.
